# 全周探索・近さ優先・手動並べ替えの区別（2026-11-02）

2026-11-03に「高評価」「レビュー数」の評価なし除外と、同程度の近さでの指標比較を変更した。最新仕様は [RATING_SEARCH_SELECTION.md](RATING_SEARCH_SELECTION.md)。以下の足切りなし・微差を先に比較する記述は変更前の記録。

後続の実在地域での問題と最新の方向別補正は [DIRECTIONAL_CALIBRATION.md](DIRECTIONAL_CALIBRATION.md) を参照。以下の「四方向の検索中心」の検証だけでは、実際の候補の地域分散を十分に検証できていなかった。

この仕様は、これまでの「高評価は星4.0以上・口コミ10件以上」「レビュー数は件数ありを必須」「評価系の初期表示は評価・件数順」を置き換える。

## ユーザーが定義した優先順位

- 目的地の種類を問わず、現在地または指定地点を中心に周囲の全方向を探索する。
- 検索での候補選びと初期表示は、指定時間・距離の上限への近さを最優先にする。
- 高評価・レビュー数は、その上での参考指標とする。低評価・レビューなしだけを理由に、近い候補を候補母集団から外さない。
- 手動の並べ替えは検索条件とは別。取得済みの同じ候補をGoogle評価・レビュー数の純粋な降順で並べてよい。追加の候補検索・経路API呼出し・候補数の変更・新たな候補の取得はしない。

## 地理的な偏りの原因と修正

1. 従来は高評価・レビュー数だけNearbyをPOPULARITYで取得していた。ほかの種類と同じDISTANCEへ統一し、検索中心の周辺で候補を取得する。施設分類の条件（自然／観光）は維持する。
2. 初期探索は対向する二方向だが、残りの補正を同じ最良方向へ繰り返すと、五つの検索枠の大半が一地域に集中する。現在は初期二方向→未探索の直交二方向→最後に最良方向の補正、の順で全四方向を確認する。時間の見積もりには各方向の経路実測を使い、上限超過・大迂回の対策は維持する。
3. 検索順で評価が距離・時間の予測誤差より先に比較されていた箇所を修正し、誤差を先に比較する。最終候補も実際の時間・距離を先に比較し、評価は同じ値の候補でのみ比較する。
4. 検索直後に高評価モードなら評価順、レビュー数なら件数順へ自動切替していた。全モードで「条件に近い順」を初期表示にする。利用者の明示的な操作による並べ替えは従来の純粋な評価・レビュー数順のまま維持する。

全方向を探索することと、最終8件を方位ごとに均等にすることは区別する。実測コストが同程度（上限の3%幅）の候補間で方向を分散するが、方向を均等にするために大幅に短い候補へ置き換えることはしない。道路網・海・施設分布によっては、近さ優先の結果として特定地域が多くなることはある。

## APIと既存仕様

Nearby最大5回、経路最大24回の呼出し上限は維持する。実際の経路時間・距離の上限判定、往復の合算、下限未満の補充、訪問済み・興味なしの除外、追加検索の重複除外は維持する。

「さらに調べる」は前回と同じ起点・条件で探索位置を回転させ、同様に四方向を探索する。元のカードの順序と内容を保ち、新しい候補を末尾へ追加する。手動で並び替えた後も、追加時には既存カードを全件再ソートしない。

## 自動検証

全2,515件合格、型検査と本番ビルド成功。

追加した43件では、時間／距離 × 片道／往復 × 初回／追加 × 全5種類で、最初の四つの候補検索の中心が四方向へ分かれることを検証する。高評価の候補を一方向だけに集中させた合成データでも、全方向をDISTANCEで取得し、上限付近の結果を採用する。すべて・高評価・レビュー数で同じ地理範囲と候補集合になること、低評価や口コミなしの近い候補が高評価の短い候補より優先されることも検証する。既存の評価／レビュー数の手動並べ替えのテストは維持する。

合成道路網の1,536組合せでも、上限の90%以上の候補を得られることと、上限超過を返さないことを維持した。これは合成条件下の回帰検証であり、全実在地域で候補数や上限への一致を保証するものではない。

## 公開版での確認

東京駅・車・高速利用可・往復120分・下限空欄の「高評価」では、8件・114〜120分、千葉県と埼玉県に分かれた候補を取得した。初期表示が条件に近い順であることも確認した。施設名・住所・写真・IDはドキュメントへ保存せず、集計値だけを記録する。

「レビュー数」も8件・114〜120分・千葉県／埼玉県の候補となり、「高評価」と候補集合が一致した。初期表示は両方とも条件に近い順。手動でレビュー数順にすると8件のID集合を保ったまま件数の降順になり、Google評価順では評価の降順になった。追加の検索APIは呼んでいない。

手動でGoogle評価順へ変更した後に「さらに調べる」を実行すると、8件から16件になり、元の8カードの表示テキスト・順序が完全に保持された。追加後の地域は千葉県・埼玉県・東京都となった。

「すべて」の同条件でも8件が千葉県／埼玉県に分かれ、「高評価」「レビュー数」と同じ候補集合となった（表示時間の一部は経路の再計算により1分程度変動した）。検索対象の種類によって取得方式が別地域の人気順へ切り替わっていないことを、公開版でも確認した。
