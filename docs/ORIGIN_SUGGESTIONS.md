# 出発地点の入力候補とログイン導線（2026-11-02）

## 入力候補

- ログイン済みの画面で2文字以上入力し、450ms入力が止まるとGoogle Places Autocomplete (New)へ問い合わせる。日本語・国内の候補を住所付きで最大5件表示する。日本全域の検索バイアスを明示し、サーバーのIP位置に候補が引っ張られないようにする。日本語IMEで変換中は取得を始めない。
- 矢印キーとEnter、またはタップ／クリックで候補を選べる。候補は自動選択しない。未選択で検索した場合は従来の手入力検索を維持する。
- 選択した場所だけPlace Details (New)のid・locationを取得し、座標を確定する。選択中は検索を止め、確定後に選んだ名称と地域を表示する。
- 検索では確定した座標を直接使用し、曖昧な入力文字列から別の場所を再解釈しない。名称は表示専用のoriginLabelで引き継ぐ。入力し直すかGPSを使うと選択状態を解除する。空欄での検索は従来どおりGPSを取得する。
- 遅れて返った候補で新しい入力や選択状態を上書きしない。フォーカスを外す・Esc・文字数不足・座標入力・選択後は候補を閉じる。失敗や利用上限時は手入力が可能なことを案内し、架空の候補へは切り替えない。

## APIと利用量

APIキーはサーバー側だけで使用し、既存のPlaces API (New)のキーを使う。ブラウザから同一サイトのPOST /api/originへ送信し、Workerでログイン、同一Origin、入力形式、本文サイズ、共有利用枠を確認してからGoogleを呼ぶ。戻り値にキーは含めない。候補・住所・座標はブラウザの画面を開いている間だけ扱い、ストレージやレスポンスキャッシュへ保存しない。Google Mapsの出典を候補欄に明示する。

Autocompleteと確定用Detailsに同じUUIDセッショントークンを使い、地点選択後は新しいセッションに切り替える。Detailsのフィールドはid・locationだけに限定し、写真や評価、不要な施設詳細を取得しない。

候補提示と座標確定のAPI呼出しは、目的地検索の1日5回とは別枠。一般アカウントは両処理の合計で1日30回・1分12回、一般全体は1日100回・直近32日1,000回まで。Durable Objectで予約を原子的に実施し、共有枠の確認に失敗した場合はGoogleを呼ばない。失敗した外部リクエストでも予約回数は消費する。管理者は従来方針どおり制限を免除し、一般全体のカウントには加算しない。入力文字列・地点名・座標は利用量ストレージへ保存せず、匿名化したアカウントIDとカウンターだけを保存する。

この上限は費用抑制用であり、Googleの請求上限を保証するものではない。同じGoogle Cloudプロジェクトの他サービスや管理者の無制限利用は別途考慮が必要。

## 未ログインの訪問

トップページのGET/HEADに有効なログインがなければ、検索画面ではなくログイン画面へ案内する。すでにログイン済みで/loginを開いた場合はトップへ戻す。規約・プライバシーポリシーはログイン前でも読める。Google認証からの復帰先、管理者と一般利用者の権限分離は維持する。

## 確認

16件の追加テストで、選択座標の保持、不正・匿名・別サイトリクエストの拒否、並列リクエストの利用制限、目的地検索の残回数を消費しないこと、未ログイン時の画面遷移を検証。既存を含む2,531件の自動テストが合格した。

公開版で「東京」から5件の候補に東京駅が含まれること、矢印キーとEnterで選んだ東京駅が住所付きで確定することを確認した。

プライバシーポリシーには、候補表示のため入力途中の地名・住所をGoogleへ送ることと、候補APIのカウンターの取扱いを追記した。

実画面では候補選択後に「東京駅発」として8件の目的地を取得し、手入力へ変更すると選択済み状態が消えることも確認した。スマホ幅390pxでは横方向のはみ出しがなく、候補をクリック／タップして大阪市を選択できた。日本全域の検索バイアスを設定した版では「東京」の先頭候補が東京駅となった。

通常のログアウト後にトップURLへアクセスすると/loginへ移動してGoogleログインを促すこと、そこから従来の管理者アカウントで再ログインすると検索画面へ戻ることを公開版で確認した。検証後は画面幅の一時変更を解除した。
