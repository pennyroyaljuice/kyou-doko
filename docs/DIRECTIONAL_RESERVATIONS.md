# 方向別の経路枠と探索履歴（2026-11-02）

## 維持する優先順位

上限への近さを最優先する。同程度とは従来どおり上限の3%幅の帯とする。149分の代わりに別地域130分を選ぶような均等配分はしない。下限以上の実測候補を優先し、不足時は下限未満を補充する。上限超過は採用しない。手動の評価・レビュー数ソートは同じ取得結果内の並べ替えであり、初期採用とは別。

## 予約の単位

候補が得られている未確認方位には、最初の1候補を経路確認する枠を予約する。方位は出発点を中心とする8方向で分類し、起点100m以内は別グループにする。未確認方位の代表候補を先に確認し、その後の余剰枠は上限への近さを改善する確認へ使う。未知の全スポットを網羅する保証ではない。

未実施の直交方向の位置補正についても、最大2回の経路枠を残す。初期二方向・直交二方向・最後の補正という最大5回のNearby探索は維持する。実測補正は方向ごとに行い、別方向の速度を流用しない。

往復候補は往路開始前に2枠まとめて確保する。経路なし・往路だけで上限超過なら未使用の復路枠を解放する。残り1枠しかないときは、新しい往復候補の確認を開始しない。従来のテストの「全件超過でも必ず24回使用」は「往復を開始できる23回で停止」に変更した。通常の24回上限は引き続き検証している。

候補は1件ごとに実測結果を反映して次の候補を選ぶ。これにより、予算終盤に2件を同時に誤った予測で確認してしまうことを避ける。位置補正の候補は、他方位の予約で後回しになっても、未確認のまま消去しない。

件数補充時も探索目標を上限の75%へ落とさない。下限未満を補充するための予測上の下限緩和と、上限に近づける探索目標は分けて扱う。

## 隣接スポットの扱い

近さの帯が同じ候補の中で、既に採用・確認対象となった場所の周囲にある候補を後回しにする。近接判定は起点からの直線距離の8%、最小250m・最大10km。これは距離の違う検索で同じ固定半径を使わないための実装上の基準であり、道路距離ではない。

同一方位の候補列にもこの基準を適用する。近さの帯をまたいで短い候補を優先することはない。市区町村や名前を使った上限・足切りは設けない。候補が近接地点しかない場合は、その候補も使って最大8件まで補充する。

## 探索履歴

成功した検索ごとに、方向別の探索中心数、除外・既出を省いた候補数、候補の経路確認回数、経路なし、上限超過、下限以上、下限未満、採用数、予算予約により確認を見送った数を集計する。方向の事前経路確認と候補の往復経路の回数は分け、合計を24回以内として検証する。

サーバーログ `SEARCH_AUDIT` にはこの集計だけを出力する。アカウント、出発地、座標、施設名、Place ID、写真情報、APIキーは含めない。ログ基盤の永続保存は新たに有効化していない。

管理者の検索応答にだけ履歴を添付する。画面下の「探索履歴（管理者）」で初回と追加検索の直近10回を閲覧できる。ブラウザーの画面状態だけで保持し、再読込・別の通常検索でリセットする。一般アカウントには応答にも画面にも含めない。追加検索でも以前のカードと順序を保つ。

探索中心の方位と、取得候補の実際の方位は区別する。ある方位の候補が0件でも、地域全体に施設が存在しないとは結論しない。候補なし・探索失敗・未探索は履歴から区別して確認する。
